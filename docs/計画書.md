# お姉ちゃんの小動物グッズショップ 計画書

Oct 28, 2026 · @なつみ

## 目的と前提

メルカリの手数料（10%）を下げるため、お姉ちゃん専用のネットショップを作る。カード決済は Stripe（手数料3.6%）。3,000円の商品1つで、手数料は300円から108円になる。

| 売り方 | 手数料 | 3,000円が売れたとき |
| --- | --- | --- |
| [メルカリ](https://help.jp.mercari.com/guide/articles/65/) | 10% | 300円 |
| [BASE](https://baseu.jp/6685)（無料プラン） | 3.6%＋40円＋3% | 約238円 |
| 自作サイト＋[Stripe](https://pay.jp/column/stripe-fees-guide) | 3.6% | 108円 |

Stripe と BASE の数字は2026年のまとめ記事のもの。公式ページはこの開発環境から開けなかったので、申し込む前に公式で確かめる。

先に知っておくこと：

- **お客さんは自分で集める**。メルカリのように人が見に来る場所ではない。インスタなどから案内する
- **匿名配送は使えない**。お姉ちゃんの名前で発送する
- **特定商取引法の表記が必要**。売り手の名前・住所・電話番号を載せるのが原則（住所の扱いは「未決定・要確認」に書く）

## 最初に作る機能（MVP）

「お客さんが1つ買えて、お姉ちゃんに注文が届く」ところまでを最初のゴールにする。カートで複数まとめ買い、クーポンなどは後回し。

### お客さん側（ショップ画面）

スマホ版を先に作り、そのあと PC でも見やすくする（画面の幅に合わせて並びが変わる作り＝レスポンシブ）。

- **商品一覧**：写真・名前・値段・「在庫あり／残り◯個／受注生産（約◯日でお届け）／売り切れ」を表示
- **商品ページ**：写真を複数枚（横にスワイプで切り替え、1枚ごとにキャプション）、飾り付きの説明文、選択肢ごとの値段、地域ごとの送料、お届けの目安
- **買うときの入力欄**：その商品に設定された質問に答える（例：文鳥・オカメインコどちら用か、色の希望）。値段が変わる選択肢は、選ぶとその場で合計金額が変わる。「必須」の質問は空だと先に進めない
- **お届け先の入力**：名前・郵便番号・都道府県・住所・メール・電話（任意か必須かは管理画面の設定しだい）をこのサイトで入力。都道府県を選んだ時点で送料と合計金額を表示
- **ログイン（任意）**：Google か、メールに届くリンクでログイン（パスワードなし）。ログイン中は保存したお届け先が自動で入り、その場で変えることも「この住所を保存」を選ぶこともできる。ログインしなくても買え、その場合もスマホの自動入力が効くように入力欄を作る
- **マイページ**：登録情報（名前・お届け先・電話）の確認と変更、お届け先を複数保存（自宅・実家など）、注文履歴（状態・追跡番号・「受け取りました」ボタン）、退会（保存した情報をすべて消す）
- **メッセージ**：注文ごとに LINE 風の吹き出しでお姉ちゃんとやり取り（注文ページかマイページから）。完了から30日まで書ける。新しいメッセージが来たらメールでお知らせ
- **レビュー**：受け取ったあと、いつでも星5段階とコメントを書ける（1注文の1商品につき1つ）。表示名はニックネーム。お姉ちゃんが確認してから商品ページに載り、平均の星も表示する
- **購入ボタン**：Stripe のお支払い画面へ移動して、カード番号だけを入力（カード番号はこのサイトを通らない）。お届け先は前の画面で入力済みなので、Stripe 側で別の地域に変えられて送料がずれることがない
- **購入完了ページ**：「ご注文ありがとうございます」と注文番号
- **固定ページ**：特定商取引法に基づく表記、プライバシーポリシー、お問い合わせ（メーラーが開く）

### お姉ちゃん側（管理画面）

管理画面はスマホ専用に作る。ボタンは指で押しやすい大きさにし、写真はスマホのカメラや写真アプリからそのまま選べるようにする。

- **ログイン**：お姉ちゃんの Google アカウントだけが入れる
- **商品の登録・編集**：名前、説明、基本の値段、使う送料表、写真（スマホから撮ってそのまま追加、20枚まで、1枚ごとにキャプション、並べ替え可、1枚目が一覧の表紙）、公開／非公開
- **説明文の飾り**：太字、文字の色、文字の大きさ（大・中・小）、マーカー、中央寄せ、箇条書き。色は可愛い色のパレットから選ぶか、自分で好きな色を登録して使い回せる。飾りのボタンはスマホのキーボードの上に並べる
- **在庫の設定**：「在庫数」か「受注生産＋お届けまでの日数」を商品ごとに選ぶ。在庫が0個になったとき「売り切れにする」か「受注生産に切り替える」かも、商品ごとに選べる
- **質問の設定**：商品ごとに質問を追加（自由入力／選択肢から選ぶ、必須かどうか）。選択肢には追加料金を付けられる（例：Lサイズ +500円、名入れあり +300円。値引きのマイナスも可）
- **送料表の設定**：配送方法ごとに送料表を作る（全国一律、または都道府県ごと）。地方単位でまとめて入れてから、県ごとに直せる。商品ごとにどの送料表を使うか選ぶ
- **注文一覧**：新しい順。お客さんの答え、お届け先、金額、状態（入金済み→制作中→発送済み）を確認・変更
- **メッセージ**：注文ごとの吹き出し画面で返信。未読がある注文には印を付ける
- **レビューの確認**：新しいレビューはメールでお知らせ。「載せる」か「載せない」を選び、ショップからの返信を付けられる。低い評価だけ載せないと信用を失うので、載せないのはひどい言葉や個人情報があるものにする。お姉ちゃんや家族が自分でレビューを書かない（ステマ規制）
- **ショップ設定**：注文時の電話番号を「任意」か「必須」か選ぶ、自分で登録した色の管理、お客さんの個人情報を消すまでの期間（短くするときは、すぐ消える件数を表示して確認してから変更）など

### 決済

- Stripe Checkout（Stripe が用意するお支払い画面）を使う。カード情報を自分で預からないので、セキュリティの責任が軽い
- 値段（基本の値段＋選んだ選択肢の追加料金）と送料（送料表×お届け先の都道府県）は**サーバー側で計算し直す**（画面の数字を書き換えられても、正しい金額しか請求されない）
- 支払いが終わったことは Stripe からの通知（Webhook）で確認してから「入金済み」にし、在庫を1つ減らす

### 通知メール

- お客さんへ：注文確認メール（注文内容・質問への答え・お届け目安）
- お姉ちゃんへ：「新しい注文が入りました」メール
- 発送したら、管理画面で配送会社と追跡番号を入れてお客さんへ「発送しました」メール。お客さんが「受け取りました」を押したらお姉ちゃんへメール（詳しくは「注文のあとの流れ」）
- 新しいメッセージ：受け取った側（お客さん or お姉ちゃん）へお知らせ。続けて届いたときはまとめて送り、メールが増えすぎないようにする
- 新しいレビュー：お姉ちゃんへ「確認してください」

## 仕組みとデータの形

クイズ集と同じ道具を使うので、間違いにくく、新しいセッションでもそのまま引き継げる。

| 役割 | 使うもの |
| --- | --- |
| 画面 | React（スマホ優先、PCでも崩れない） |
| サイトの置き場所 | Firebase Hosting |
| 商品・注文のデータ | Firestore |
| 商品写真 | Firebase Storage |
| ログイン | Firebase Authentication（お客さんは Google かメールに届くリンク。管理画面に入れるのはお姉ちゃんのアカウントだけ） |
| 金額計算・決済・メール | Cloud Functions（サーバー側のプログラム） |
| カード決済 | Stripe Checkout |
| メール送信 | Gmail 経由（クイズ集の購入通知と同じやり方） |

### 注文から発送までの流れ

1. お客さんが商品ページで選択肢・質問に答え、お届け先を入力して「購入」を押す
2. サーバーが商品データと送料表から、値段（基本＋選択肢）と送料（都道府県で決まる）を計算し、在庫を確かめて、「支払い待ち」の注文を作る
3. Stripe のお支払い画面でカードを入力
4. Stripe から「支払い完了」の通知 → 注文を「入金済み」にし、在庫を減らし、両方にメール
5. お姉ちゃんが管理画面で「制作中」「発送済み」に切り替える → 発送済みメール → お客さんが「受け取りました」を押して完了

最後の1個を同時に2人が買おうとした場合は、先に支払いが完了した人を優先する。後の人は自動で返金してお詫びメールを送る（この扱いは実装時に確定）。

### データの形

| 入れ物 | 主な中身 |
| --- | --- |
| 商品（products） | 名前、基本の値段、使う送料表、飾り付きの説明文、写真（最大20枚。それぞれにキャプションと並び順）、公開／非公開、在庫の種類（在庫数 or 受注生産）、在庫数、在庫0個のときの扱い（売り切れ or 受注生産に切替）、お届けまでの日数、質問のリスト |
| 質問（商品の中） | 質問文、答え方（自由入力 ／ 選択肢）、選択肢とそれぞれの追加料金、必須かどうか |
| 送料表（shippingTables） | 名前（例：ゆうパック60サイズ）、全国一律か都道府県ごとか、47都道府県それぞれの送料 |
| 注文（orders） | 商品、選んだ選択肢と追加料金、個数、金額、送料、質問への答え、お届け先（都道府県を含む）、メール、状態、追跡番号、日時 |
| お客さん（customers） | ログインした人の名前、メール、電話、保存したお届け先（複数）。読めるのは本人とお姉ちゃんだけ |
| ショップ設定（settings） | ショップ名、自分で登録した色のリスト、電話番号を任意にするか必須にするか、個人情報を消すまでの期間 |
| メッセージ（注文の中） | 送った人（お客さん or ショップ）、本文、日時、既読かどうか |
| レビュー（reviews） | 商品、注文、星の数、コメント、ニックネーム、状態（確認待ち／掲載／非掲載）、ショップからの返信、日時 |

注文には、そのときの値段・追加料金・送料をそのまま記録する。あとで商品の値段や送料表を変えても、過去の注文の金額は変わらない。

### 写真と説明文の保存のしかた

- 選んだ写真は、アップロードする前にスマホの中で WebP に変換して小さくする。サーバーで変換しないので、変換の費用は0円
- 大きさは2種類作る：商品ページ用（長い辺1600px）と一覧用（長い辺600px）。一覧が速く開く
- 変換には、どのブラウザでも同じように動く変換プログラム（jSquash）を使う。2026年10月28日にこのセッションで、テスト画像（1600×1200）が WebP に変換できることを確認済み。本物の写真でどれくらい軽くなるかは、作るときに確かめる
- 未確認：iPhone の写真形式（HEIC）を選んだときにそのまま変換できるか。作るときに iPhone で確かめる
- 写真を差し替えたり削除したりしたら、古いファイルも消す（無料枠を無駄に使わない）
- 説明文は、決めた飾りだけを許す形で保存する。何でも書ける形（HTML そのまま）にすると、悪意のある書き込みでお客さんの画面が乗っ取られるおそれがあるため

注文にはお客さんの住所が入るので、読めるのはお姉ちゃんだけにする。リポジトリは公開だが、データはリポジトリには入らない。

## 注文のあとの流れ（お金・発送・受け取り）

### お金の流れ

- お客さんが Stripe で支払った時点で決済が確定し、売上はお姉ちゃんの Stripe 残高に入る。**メルカリのように「受け取りまで売上を預かる」ことはしない**。受注生産なので、作り始める前に代金が確定しているほうがよい
- Stripe 残高からお姉ちゃんの銀行口座へは、Stripe の決まった周期で自動で振り込まれる（周期と振込手数料は公式ページで確認する）
- 「受け取りました」はお金の動きとは関係ない。やり取りの区切りとして使う
- 返金は、最初は Stripe の管理画面から行う。あとでショップの管理画面に返金ボタンを付ける
- 注意：お客さんがカード会社に異議を申し立てると、後から売上が取り消されることがある（チャージバック）。メルカリと違い、この対応はお姉ちゃん側でする。配送会社と追跡番号の記録が「送った証拠」になるので、注文ごとに必ず残す

### 注文の状態

| 状態 | こうなったら | 届くメール |
| --- | --- | --- |
| 支払い待ち | お客さんが「購入」を押した | なし（支払わずにやめたものは、しばらくして自動で消す） |
| 入金済み | Stripe から支払い完了の通知 | お客さん：注文確認。お姉ちゃん：新しい注文 |
| 制作中 | お姉ちゃんが管理画面で切り替え | なし |
| 発送済み | お姉ちゃんが配送会社と追跡番号を入れて「発送した」を押す | お客さん：発送しました（配送会社・追跡番号・追跡ページへのリンク） |
| 受け取り済み（完了） | お客さんが「受け取りました」を押す。押されなければ、発送から14日で自動で完了 | お姉ちゃん：受け取りました |
| キャンセル | お姉ちゃんが返金した | お客さん：キャンセルのお知らせ |

### 発送の連絡

- 配送会社は「ヤマト運輸／佐川急便／日本郵便／その他」から選んで、追跡番号を入れる
- メールにはその会社の追跡ページへのリンクを付ける（リンクの形は、作るときに各社の公式ページで確認）。「その他」は番号だけ載せる
- 間違えたときのために、追跡番号の直しとメールの送り直しもできるようにする

### お客さんの注文ページ

- ログインしていない人も見られるように、注文確認メールに「注文の状況を見る」リンクを入れる（推測できない長い番号つきで、他人の注文は見られない）
- そこで状態・追跡番号を見られ、「受け取りました」を押せる。ログインしている人は、マイページの注文履歴からも同じことができる

### お客さんの個人情報

- 保存するもの：名前・住所・電話・メール・注文内容。発送と連絡に必要なので、サイト（Firestore）に保存する
- カード番号は保存しない（Stripe だけが持つ）
- 読めるのは管理画面にログインしたお姉ちゃん（開発中はなつみも）だけ。お客さんは自分の注文ページとマイページだけ。データベースのルールで制限し、「他人が読めないこと」を自動テストで確かめる
- 公開リポジトリには個人情報を一切入れない（テストはにせのデータ）
- プライバシーポリシーに利用目的（発送と連絡のため）を書く
- 完了から、管理画面で決めた期間（最初は2年。3か月〜5年から選ぶ）がたったら、住所・電話・メッセージを自動で消す。金額や商品などの売上の記録は残す。マイページに保存したお届け先は、本人が消すか退会するまで残す

## 費用

ショップの規模（月に数十件までの注文）なら、**毎月の固定費は0円、かかるのは売れたときの Stripe 手数料だけ**になる見込み。ただし、Cloud Functions と Storage を使うために Firebase を「従量制（Blaze）」にする必要があり、無料枠を超えたら請求される。

| 項目 | 無料枠 | このショップでの見込み |
| --- | --- | --- |
| Stripe 手数料 | なし | 売上の3.6%（公式ページ未確認） |
| Firestore（データ） | 1 GiB、読み取り 50,000回／日、書き込み 20,000回／日 | 無料枠内 |
| Cloud Storage（写真） | 5 GB、置き場所を US-WEST1 / US-CENTRAL1 / US-EAST1 にした場合だけ | 写真を小さくして保存すれば無料枠内 |
| Cloud Functions（サーバー） | 200万回／月など | 無料枠内 |
| ログイン（Firebase Authentication） | メール・Google などのログインは月 5万人まで無料。電話番号（SMS）ログインは1通ごとに有料 | 無料枠内。SMS ログインは使わない |

### お金の事故を防ぐために

- 従量制に切り替える前に、この表をなつみに見せて承認をもらう
- 予算アラート（例：月100円を超えそうになったらメール）を先に設定する
- 合鍵（Stripe の秘密の鍵など）をデプロイのたびに作り直さない（イントロベットの ¥526 と同じ失敗をしない）
- 関数のコードが変わっていないときは、関数を作り直さない

## 作っている間に無料枠を超えない工夫

これまでの超過は、作っている途中に本物のサーバーを何度も動かしたことが原因（非公開リポジトリでの GitHub Actions、デプロイのたびの合鍵の作り直しや関数の作り直し）。このショップでは、**作っている間は本物の Firebase をほぼ使わない**。

### 1. 練習用の「にせ Firebase」で作る

- Firebase には、開発環境の中だけで動く練習用のコピー（エミュレーター）がある。データ・ログイン・写真置き場・サーバー側の計算を、Google のサーバーを使わずに動かせるので、何回試しても 0 円
- プロジェクト名を「demo-」で始めると、本物のサービスにはつながらない（つなごうとすると失敗する）。間違って本物を使う事故を防げる
- 2026年10月28日にこのセッションで実際に起動し、商品データの保存、写真の保存、サーバーでの金額計算（3,000円＋Lサイズ500円＋北海道の送料 1,200円＝4,700円）が動くことを確認済み
- 自動テストもこの練習用で動かす。公開リポジトリなので GitHub Actions も 0 円

### 2. 本物に上げるのはステップの区切りだけ

- なつみがスマホで触って確かめるときだけ、本物の Firebase に上げる。push もまとめて行う
- サーバー側のコードが変わっていないときは、関数を作り直さない（画面だけの修正なら Hosting だけ更新）
- 関数の保管場所には「古いものを自動で消す設定」を最初に入れる（firebase-tools にこのためのコマンドがあることを確認済み）
- 合鍵（Stripe の秘密の鍵など）は最初に1回だけ登録し、デプロイでは作り直さない
- 関数を「常に待機させる」設定は使わない（待機中も請求されるため）

### 3. 作り方で減らす

- 写真はアップロードする前にスマホの中で小さくする
- 画面がデータを読み続ける作り方（開いている間ずっと監視し続けるなど）をしない。商品一覧は必要な分だけ読む。メッセージの新着を確かめるのは、その画面を開いている間だけ
- Stripe はテスト用の口座で試す（本物のお金は動かない）

### 4. 見張り

- 予算アラートは「メールが来るだけ」で、請求を自動で止めるものではない。なので作っている間は、本物に上げたあとごとにこちらで使用量を確かめて報告する

### 注意

Stripe のサーバー（api.stripe.com）には、今のセッションの通信設定ではつながらない。練習用では Stripe の代わりに「お支払いが終わったふり」の通知を作って試し、本物のテスト決済は本物の Firebase に上げてから行う（または新しいセッションの通信設定で Stripe を許可する）。
